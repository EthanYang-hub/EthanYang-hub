# Waybill Image Generation Service

## Company

SF Technology

## Role

Java Backend Engineer

## Period

2018 - 2019

## Project Summary

Optimized a shipment image generation service used by business teams to view waybill-related images across different regions and delivery scenarios.

## Business Context

The original system generated and stored large volumes of shipment images in advance. These images were used by internal teams to review delivery-related information, but the architecture created high storage pressure and unnecessary processing overhead.

## My Responsibilities

- Analyzed the legacy image generation workflow
- Participated in redesigning the generation strategy
- Optimized backend processing logic for better response time
- Helped move the system from pre-generated output to on-demand generation
- Improved storage efficiency and runtime performance

## Tech Stack

Java, Spring, Hibernate, Redis, MySQL, OSS, runtime image composition

## Challenges

The main challenge was reducing storage and processing cost without affecting usability for business teams. The old model generated large volumes of images whether they were viewed or not, which wasted both storage and compute resources.

## What I Did

I helped redesign the service into an on-demand image generation model and supported an approach based on reusable image components instead of fully generating every image in advance. This reduced redundant processing and improved delivery efficiency.

## Outcome

- Reduced storage usage by about 90%
- Improved image generation latency from around 1 second to around 300 ms
- Made the legacy workflow more efficient and more sustainable operationally

This project strengthened my experience in legacy-system optimization, backend performance improvement, and infrastructure cost reduction.
